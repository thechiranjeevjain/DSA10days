# Mutation Switchboard

Learn this file as pattern-switch grammar. For every near-miss, ask: why not now, what is missing, what minimal change makes it work, and why does it work after the change?

| Current winner | Near pattern | Why not now | What is missing | Minimal change | Now why it works |
|---|---|---|---|---|---|
| HashMap / Frequency / Set | Two Pointers | Order is not giving a safe elimination rule. | Sorted ends, palindrome symmetry, or shrinkable pair bounds. | Make the input sorted and ask for one pair or in-place validation. | A left/right move can discard impossible pairs without storing all seen values. |

| Intervals / Sorting Greedy | Dynamic Programming | Greedy fails when local choice can block a better weighted future. | Weights/profits or incompatible choices requiring optimal value. | Add profit to intervals and ask for max profit schedule. | Choosing or skipping an interval creates repeated optimal subproblems. |
| Backtracking / Combinatorial DFS | Dynamic Programming | Backtracking enumerates outputs; DP collapses repeated states when only an optimum/count is needed. | Repeated state identity and no need to list every solution. | Ask for count/minimum/best value instead of all combinations. | Memoized state replaces explicit path enumeration. |
| Backtracking / Combinatorial DFS | Trie | Backtracking alone does not share dictionary prefixes. | Many word-prefix lookups while exploring characters. | Add a dictionary of words and ask for all words on a board. | Trie prunes impossible prefixes early. |

| Trie | Backtracking | Trie is the dictionary accelerator; search still needs DFS only when paths are generated. | Need to try/undo board paths or wildcard branches. | Ask for all dictionary words formed by adjacent board cells. | DFS explores paths while Trie rejects dead prefixes. |
| Dynamic Programming | Greedy | DP is needed when a local choice can harm a future state. | A proof that the locally best choice remains globally safe. | Constrain the problem so earliest finish, farthest reach, or cheapest immediate choice is always safe. | The state collapse becomes a local invariant. |
| Dynamic Programming | Backtracking | DP returns an optimal/count value; backtracking is needed when every concrete solution must be emitted. | Output requires listing all paths/combinations/permutations. | Change output from minimum/count to all valid configurations. | The path itself becomes part of the answer. |

| Greedy | Intervals/Greedy | General greedy needs a concrete ordering that makes the local choice safe. | Interval start/end structure. | Express the problem as selecting/merging sorted intervals. | Sorted endpoints give the local decision a proof. |
